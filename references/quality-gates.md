# Quality gates: use on every run

All examples are run-relative. Resolve each `scripts/` path relative to the skill directory and replace `RUN` with the absolute run directory. Do not manually write or edit schema-v3 `run-state.json`. `gate.py` is the only transition writer; it returns nonzero and leaves state unchanged when a check fails. It checks recorded declarations and file hashes; it is not a scheduler, proof of a real agent dispatch, source correctness, a license to use a paper, or proof of completeness. Inspect actual task histories and source content, and reconcile the event list with real subagent messages at final review. Direct filesystem edits can bypass the script and are a protocol violation, not a security boundary.

## 1. Focus question first; discovery second

1. Initialize with `scripts/init_run.py`. Before discovery, save `01_plan/scope.md` and a proposed `01_plan/core-question.json` following `references/core-question.md`. The question record must name the task/context, focal method or phenomenon, outcome/trade-off, conditions, inclusion/exclusion boundaries, a working title and at least two searchable subquestions. Record assumptions and distinguish the preliminary map from the final chapter outline.
2. `python scripts/gate.py --run-dir RUN advance searching` checks the proposed question's structure. Run a bounded pilot across its subquestions and save the actual queries, sources, result volume, existing-review coverage and synthesis-gap assessment in `02_search/pilot-search.md`. Compare related reviews in `02_search/prior-reviews.json`, recording search provenance, verified records (or why no direct predecessor was found) and the proposed contribution. If the topic is too broad, too narrow or already covered, revise the question and repeat a bounded pilot. When the primary agent judges it focused, distinct and feasible, set `status` to `locked` and add the pilot decision and assessments to `core-question.json`, including `pilot_search.prior_reviews_artifact`. Only then start full discovery; build source-specific queries from the locked subquestions.
3. Save the complete full-search record in `02_search/search-log.md`, then run `python scripts/gate.py --run-dir RUN advance evidence`. This requires a locked question and feasible pilot report, and stores hashes of the locked question, scope, pilot report and prior-review comparison. A material change to any of them requires a fresh run because the search base has changed.
4. Record the actual candidate queue in `04_evidence/coverage.json` with the schema below. Ask research delegates to resolve all important pending candidates, verify identity/title against the original source, follow citations in both directions and obtain lawful full text. Keep original version distinctions. Update the ledger as work proceeds; do not mark known unavailable sources as successful.
5. `python scripts/coverage.py RUN/04_evidence/coverage.json --run-dir RUN --output RUN/08_audit/coverage-report.json`. On insufficient coverage delegate further search or lawful evidence acquisition. The final manuscript has a hard bibliography threshold of at least 40 unique cited works, with at least 60% from the latest five publication years; this is measured on the final cited bibliography, not raw search results or all included candidates. `coverage.py` checks topic-level evidence coverage and does not calculate this final bibliography distribution. Search with enough margin to meet the final threshold, include multiple perspectives and criticism, and never pad with irrelevant citations. Record venue/field/date breadth and actual inaccessible sources. If source retrieval, citation tracking, core evidence or the final bibliography threshold remains insufficient after bounded work, first stop and cancel any active delegate, then run `python scripts/gate.py --run-dir RUN limited --reason "specific unresolved gaps"`; save useful artifacts and report a limited draft without further user interaction. Never mark a paper excluded or not important merely to get past the gate.
6. Before `python scripts/gate.py --run-dir RUN advance outline`, complete `04_evidence/appraisal.json`, `04_evidence/synthesis-matrix.json` and `08_audit/evidence-synthesis-review.json` as specified in `references/evidence-synthesis.md`. The review must bind to the current coverage, appraisal and matrix hashes and pass criteria-fit, source-grounding, cross-study-synthesis, counterevidence and contribution checks. The gate checks structure and bindings; the primary agent judges scientific content. Then finalize `01_plan/outline.md` and `01_plan/sections.json`. Every section lists the subquestion IDs and synthesis IDs it answers; all subquestions and synthesis units must be mapped. If evidence or synthesis artifacts change before drafting, update the outline/section manifest and run `python scripts/gate.py --run-dir RUN refresh-evidence --reason "updated outline and synthesis after new evidence"`; this refreshes the evidence lock without changing the core question. Now advance drafting. If anything changes after drafting begins, update the appraisal, synthesis assets and review, revise the outline if mappings change, then use `reassess` from the earliest affected section; accepted sections and evidence are hash-checked.

The gate validates the question record's structure, locked hashes and outline mapping; the primary agent must still judge whether the question is focused, answerable, distinct from existing reviews and supported by enough evidence. Do not treat the JSON schema as proof of intellectual quality.

## 2. Coverage ledger contract

Each topic record includes `question_ids`, mapping its searches and evidence to one or more locked subquestions. The union of topic mappings must cover every subquestion.

The JSON object contains `topics` and `candidates` arrays. Every topic has `id`, `core` boolean, `searches` (entries `source`, `query`, `date`, `status` = `ok`/`failed`/`unavailable`), and `citation_tracking` containing `forward` and `backward` with `status` = `done`/`unavailable` and a specific `details` string (seed IDs, searched source, results and stopping reason). Unavailable tracing remains insufficient; try another route or deliver limited. Each core direction defaults to `minimum_primary: 2` and `minimum_fulltext: 1`, configurable for the domain with a substantive `threshold_reason` for reducing the former. These are per-topic safeguards, not a claim of adequate coverage. Ensure each main conceptual direction from the user's actual scope appears: omitting a topic is not a valid way to pass.

Each candidate has unique `id`, `title`, `verified_title` read from a primary source, `identifier` (`arxiv:2302.11939`, `doi:10....` or `pmid:...`), `verified_url` to the checked source, `topics` IDs, `status` = `pending`/`included`/`excluded`/`unverifiable`, `kind` = `primary`/`review`/`other`, `access` = `metadata`/`abstract`/`fulltext`, and boolean `important`. Excluded/unverifiable records need a specific `reason`; important pending/unverifiable records block the gate. Included records need exact normalized matching title and verified_title, a recognized identifier and URL; this is a structural check, not an external verification. When `fulltext` is included, provide `evidence_file` (a nonempty file inside RUN containing source-grounded evidence) and `locator` (page, section, figure, or equivalent actually observed). Do not use a PDF page number unless verified. Avoid duplicate IDs for the same paper: the checker matches arXiv identifiers and their DataCite DOI forms, but does not automatically unify preprint and venue publications.

Example only (replace all sample values with actual checked evidence; no production claims):

```json
{"topics":[{"id":"methods","core":true,"question_ids":["Q1","Q2"],"minimum_primary":2,"minimum_fulltext":1,
  "searches":[{"source":"arxiv web","query":"EXAMPLE","date":"2026-10-27","status":"ok"}],
  "citation_tracking":{"forward":{"status":"done","details":"seeds and searched index"},"backward":{"status":"done","details":"seeds and reference lists"}}}],
 "candidates":[{"id":"paper-a","title":"Example A","verified_title":"Example A","identifier":"arxiv:2302.11939",
  "verified_url":"https://example.org/a","topics":["methods"],"status":"included","kind":"primary","access":"fulltext",
  "important":true,"evidence_file":"04_evidence/a.md","locator":"section 3"}]}
```

The sample intentionally does not meet the two-primary threshold and is not a verified paper. Track all candidate statuses and retain metadata/identity-conflict and excluded records, not just final citations.

## 3. Outline, chapter dispatch and acceptance

`01_plan/sections.json` is a nonempty list in **writing order**, each entry like `{"id":"S1","priority":1,"reason":"foundational synthesis","question_ids":["Q1"],"synthesis_ids":["SYN1"],"depends_on":[]}`. `question_ids` must refer to locked subquestions and `synthesis_ids` to accepted synthesis-matrix units; every subquestion and unit must appear in at least one section. Lower integer = higher importance. A higher-priority eligible section goes first; dependencies must already appear earlier. `01_plan/outline.md` separately states final reading order. `gate.py --run-dir RUN advance drafting` creates the chapter states.

For each chapter:

```text
gate.py --run-dir RUN dispatch S1 --delegate agent-id
# actually delegate the task; wait for returned artifact
gate.py --run-dir RUN submit S1 --file 05_sections/S1/draft.md
# primary agent examines prose, original source locators and actual delegate return
gate.py --run-dir RUN accept S1 --review 08_audit/S1-review.json
```

The review JSON must contain section_id, decision (accept or revise), a nonempty reason, and claim-specific evidence findings. For acceptance, checks must set scope, evidence, consistency, synthesis, citations and defensive_writing to true. It must also contain a synthesis finding for each assigned synthesis ID, naming an integrated claim, at least two source IDs from that unit, and how relevant conditions or counterevidence were treated. The primary agent checks these against the matrix and inspected sources; the script checks IDs and required fields. The defensive-writing scan covers the whole submitted artifact, including tables and captions. If any check fails, record revise and delegate a correction. The primary agent never rewrites rejected prose. For rejection use `revise S1 --review ...`, then dispatch S1 again to a delegate and review again. Only the first unfinished chapter can be dispatched; one may be active at a time. Relevant accepted artifacts are hash-checked.

If new evidence is needed while a chapter is active, first actually stop/wait for the real delegate, then record `cancel S1 --reason "..."`; this does not itself interrupt a running agent. Update the ledger and keep researching until the coverage gate passes. Then run `reassess S1 --reason "..."`, naming the earliest affected section; it locks the new ledger and resets that section and all later ones before work resumes. This also works before the first section has ever been accepted. For an accepted chapter error without an active task, `invalidate S1 --reason "..."` resets that section and later chapters, or use reassess after changing coverage. Both clear downstream acceptance snapshots; draft/figure/frontmatter/audit stages must be rerun. A failed coverage check cannot be waived by a status update; finish as limited if the gap remains.

## 4. Figures, frontmatter and final status

Once every body section is accepted, plan at least five numbered figures and four numbered tables for the main manuscript. Five to eight figures and four to six tables are the default planning range, subject to venue limits and explanatory value. Count each separately numbered figure once; panels and supplement-only material do not count. Every figure must have a distinct purpose and nearby manuscript reference.

The figure cycle stores generation, cycle and accepted-body fingerprint in run-state.json. Copy those exact bindings to figure-review.json. Before generating images, delegate the figure plan, shared style guide and table plan. Inspect the bundled reference images. Generate the final PNG that will appear in the manuscript; there is no Draw.io recreation. The subagent must inspect the image at print size, confirm correct labels and composition, and record quality notes. Its PNG must provide 300 effective DPI at the declared print width.

Each figure record in figure-review.json must include:
- unique id, in-run png and evidence paths, the exact prompt, selected reference filenames and matching reference_inputs;
- style_review with accepted true, nonempty selected_references, applied_features and conformance_notes;
- quality_review with accepted true, actual width_px and height_px, positive intended_width_mm, legibility_notes and visual_quality_notes;
- content_review by the primary agent with accepted true, claim_evidence_alignment, labels_and_relationships_checked and unsupported_content as an empty list.
The gate compares reported dimensions with the PNG header and calculates print DPI. If an image cannot be conditioned on bundled references, explain the limitation. The primary agent opens every image and checks it against the accepted plan, evidence and paper claims. If content does not match or the image fails quality checks, preserve the rejection finding and delegate a corrected image. Do not edit a rejected image as the primary agent. Re-review all final images as a set before advancing.

The final figure image paths must match the assembled Markdown one-to-one. The accepted snapshot includes the plan, style guide, table plan, review, PNGs and evidence notes. The primary agent inserts only accepted images and delegates all figure corrections. Tables are real Markdown pipe tables with unique sequential captions immediately above each table. The primary agent checks every cell and delegates corrections.

After figures and tables pass, advance frontmatter and store a binding to the current accepted body and figure snapshot. Delegate `07_manuscript/review-approach.md`, the abstract, introduction and conclusion. The frontmatter review must include an accepted method-transparency decision checked against the actual search log; if the venue integrates methods elsewhere, record where. It must also map synthesis-matrix gaps to directions in the conclusion. Require all files and a passing review. If body evidence changes, reopen affected chapters and regenerate figures and frontmatter in order.

Delegate cross-section review and corrections. Delegate final title naming on the full stable manuscript, then check that the selected title matches the metadata and visible heading. Re-run title generation after any accepted content change.

Before final completion, save `08_audit/research-agenda-review.json`, mapping every synthesis-matrix gap ID to a concrete recommendation and a location in the accepted conclusion. The primary agent verifies each recommendation against the evidence. Save final-review.json with cross_review, citations_checked, figure_text_consistent, limitations_reported, section_integrity_checked, defensive_writing_checked, tables_checked, figure_style_conformance_checked, prior_review_contribution_checked, evidence_appraisal_checked, synthesis_contribution_checked, review_approach_checked and research_agenda_checked all true. Include source manuscript and bibliography paths with SHA-256 fields, plus the readable citation-resolved Markdown and its hash. Include the final PDF path and hash, and the PDF validation report path and hash. The validation report must have status passed, a matching pdf_sha256, a contact_sheet path inside the run, and passing checks for page_geometry, body_font, margin_overflow, sparse_pages, fonts_embedded, markdown_residue, figure_table_counts and visual_review. The primary agent must inspect the contact sheet and flagged pages, record substantive visual_review_notes, and mark visual_review true only after that inspection. Promote build/out.pdf to the final path with scripts/pdf/promote.py only after approval.

The citation audit must show at least 40 unique cited works and at least 60% from the latest five publication years. Verify the values independently against the final Pandoc citation parse and bibliography; missing years count as nonrecent. The gate checks the recorded audit but does not recalculate the distribution. The final manuscript must contain at least five numbered figures and four sequentially captioned Markdown tables. The gate verifies hashes and one-to-one figure mapping, then marks ready_for_author_review, not published or peer reviewed. If a reviewed figure, frontmatter file, manuscript or bibliography changes, reopen the affected stage and redo downstream reviews and exports. If a required deliverable remains blocked, preserve useful artifacts and label the run limited; do not claim completion.
 ## 5. Legacy and failure conditions

Version-1 and pre-synthesis schema-v2 run states are read-only to gate.py. Retain their artifacts and start a schema-v3 run for work that needs the contribution, appraisal and synthesis gates. `python scripts/audit_legacy.py --run-dir OLD_RUN --output OUTSIDE_OLD_RUN.json` summarizes declared source levels and records only; it does not verify those claims, migrate the run or establish actual coverage. Do not migrate an old run by setting its state to ready: create a new run, import actual records, reconstruct and verify missing source evidence and reviewer decisions, and retain original artifacts. If hosted web search or arXiv is unavailable, record it and try other lawful sources; reaching the count threshold does not replace coverage or full-text checks. Run state is an operational journal under a single primary writer, not a tamper-proof ledger or concurrency-safe transactional database. `limited` is terminal; retain earlier artifacts and start a new run when resuming.
